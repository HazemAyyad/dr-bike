## 3. المبيعة 4070 — Failure مغلق لكن المشكلة لم تنتهِ

الفاتورة: `SAL-0001004`
المنتج: مطور 1000 واط فراشة عريض

Snapshot السطر الفرعي 4073: 200

المشكلة:

- Allocation رقم 201: كمية 2، تكلفة 2,200، Layer 583.
- Allocation رقم 204: كمية 2، تكلفة 2,200، Layer 583.
- Movement رقم 10675: كمية -2، تكلفة 2,200.
- Movement رقم 10680: كمية -2، تكلفة 2,200.
- إجمالي Allocations أصبح 4 مقابل كمية مباعة 2.
- القيد المحاسبي الحالي رقم 14 سجل COGS بقيمة 2,200 فقط.
- مجموع Snapshots الحالي للسطر الرئيسي والفرعي هو 2,400.

الإجراء الآمن المطلوب:

1. تتبع سبب إنشاء الزوجين 201/10675 و204/10680: هل حدث إلغاء، إعادة بيع، إعادة محاولة أو حدث Observer مرتين؟
2. تحديد الزوج التشغيلي الصحيح من السجلات والتوقيت وسلسلة `reversal_of_id` إن وُجدت.
3. عدم حذف أي Allocation أو Movement قبل إثبات أنه مكرر.
4. بعد تصحيح المصدر، إعادة فحص الكمية والتكلفة ثم تحديد هل القيد 14 يحتاج تصحيحًا أو عكسًا وإعادة ترحيل.
5. يجب ألا تُعتبر Failure مغلقة نهائيًا إلا بعد نجاح فحص FIFO وتطابق COGS مع التكلفة الموثوقة.

## 5. قواعد الإصلاح المطلوبة

- لا استخدام لسعر البيع أو `wholesalePrice` كتكلفة شراء.
- لا استخدام لقيمة صفرية لإجبار القيد على النجاح.
- لا تعديل مباشر على `boxes.total` أو رصيد الذمم أو مخزون المنتج.
- لا حذف Allocation/Movement مكرر قبل إثبات مصدر التكرار.
- أي تكلفة تاريخية يجب أن تستند إلى Purchase Receipt أو Cost Layer أو Allocation موثوق ومتطابق مع المنتج والمتغير والكمية.
- عند فشل الترحيل يجب أن يبقى Failure مفتوحًا مع سبب واضح.

## 6. شروط إغلاق كل مشكلة

تعتبر الحالة سليمة فقط عندما تتحقق الشروط التالية معًا:

1. مجموع Allocation Quantity يساوي الكمية التشغيلية المباعة.
2. كل Allocation مرتبط بطبقة Cost Layer صحيحة للمنتج والمتغير.
3. لا توجد طبقة سالبة.
4. تكلفة Stock Movement تطابق مجموع Allocations.
5. `inventory_total_cost` يطابق تكلفة FIFO المثبتة.
6. قيد المبيعات يحتوي Revenue، وعند وجود منتجات يحتوي COGS وInventory بالمبلغ الصحيح.
7. القيد متوازن ولا يوجد قيد آخر نشط للمصدر نفسه.
8. بعد ذلك فقط يتم تعيين `resolved_at` للـFailure.
