# Debt Ledger accounting authority

## Active system

`debt_transactions` is the operational debt ledger for every new transaction.
Manual cash movements must be created through `POST /api/debt-ledger/transaction`,
must select a cash box, and inherit their currency from that box.

Transactions whose `source` is not `manual` are generated by their original
sale, purchase, maintenance, return, or check workflow. They are read-only in
the Debt Ledger and must be corrected from their source document.

## Legacy system

The `debts` table and the old `/api/add/debt`, `/api/edit/debt`,
`/api/show/debt`, and legacy debt-report endpoints remain available only for
compatibility with older application versions and historical reads. The current
Debt Ledger UI does not use them to create new debt movements.

No historical `debts` rows are copied automatically into `debt_transactions`.
Do not run a legacy migration or dual-write both tables without a separately
reviewed mapping and production reconciliation plan.

The legacy `/api/add/transaction` workflow still handles its non-debt cash and
check operations. Its debt portion writes only to `debt_transactions` through
`DebtLedgerService`.

## Safe running-balance check

The Security Center page at `/security-center/accounting` exposes the same
workflow for operators:

- **معاينة آمنة** lists every stored/expected running-balance difference and
  does not write anything.
- **إصلاح أرصدة دفتر الديون** requires `ACCOUNTING_REPAIR_WEB_TOKEN` plus the
  exact confirmation phrase. It repairs only `balance_after`, then displays the
  remaining accounting reconciliation mismatches.

The page never runs migrations. Apply the additive migrations separately before
enabling its repair button.

Read-only (default or explicit):

```bash
php artisan debt-ledger:check-balances
php artisan debt-ledger:check-balances --dry-run
```

Derived-field repair, only after reviewing dry-run output and taking a backup:

```bash
php artisan debt-ledger:check-balances --repair
```

Repair changes only `debt_transactions.balance_after`. It never guesses or
changes amounts, parties, types, currencies, boxes, sources, cash, or journals.
