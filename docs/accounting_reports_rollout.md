# تشغيل دفتر الأستاذ والتقارير المحاسبية

هذا التحديث يبني دفتر أستاذ مزدوج القيد فوق البيانات التشغيلية الحالية. ملف SQL الإنتاجي المستخدم أثناء التطوير كان مرجعًا للقراءة فقط، ولا يدخل ضمن خطوات التشغيل ولا يجب استيراده فوق قاعدة السيرفر.

## قبل التشغيل

1. خذ نسخة احتياطية كاملة من قاعدة البيانات وملفات التطبيق.
2. تأكد أن تحديث Laravel وتحديث Flutter متوافقان؛ إنشاء أصل أو مصروف مشروع صار يتطلب صندوق دفع.
3. اختر نافذة صيانة قصيرة، لأن أي حركة تحدث بين `migrate` وإنشاء الأرصدة الافتتاحية ستجعل دفتر الأستاذ غير فارغ وتمنع التهيئة عمدًا.
4. لا تستخدم قاعدة `.env` المحلية كتجربة لنسخة السيرفر. نفّذ المعاينة أولًا على نسخة staging منفصلة إن توفرت.

## خطوات النشر على السيرفر

```bash
php artisan down
php artisan migrate --force
php artisan accounting:initialize
```

أمر `accounting:initialize` بلا `--apply` للمعاينة فقط. يجب حل كل مشكلة مانعة، خصوصًا أرصدة المخزون التي تحمل `needs_review`، ثم تنفيذ:

```bash
php artisan accounting:initialize --apply --notes="بدء دفتر الأستاذ بعد مراجعة الأرصدة الافتتاحية"
php artisan accounting:sync
php artisan accounting:audit
php artisan up
```

لا تستخدم `--force` إلا بعد مراجعة يدوية موثقة؛ فهو يتجاوز المشاكل المانعة ولا يصلح البيانات. أمر `accounting:sync` آمن للتكرار، ويتجاهل الحالة التاريخية السابقة للتهيئة ويضيف فقط أحداث دورة الحياة اللاحقة عند الحاجة.

## شروط القبول

- `accounting:audit` ينتهي بنجاح.
- فرق ميزان المراجعة يساوي صفرًا.
- `open projection failures` يساوي صفرًا.
- `unallocated clearing` يساوي `no`.
- `reconciliation mismatches` يساوي صفرًا.
- واجهة التقارير تعرض تحذير جودة إذا خالف أي شرط بدل إظهار التقرير كأنه نهائي.
- تتم مطابقة الصناديق، المخزون، الذمم، الشيكات، الأصول، سلف الموظفين، والرواتب المستحقة مع الأرصدة التشغيلية.

## التشغيل الدوري

```bash
php artisan accounting:sync
php artisan accounting:audit --from=2026-09-01 --to=2026-09-30 --currency=شيكل
```

قبل إغلاق فترة محاسبية، عالج فشل الإسقاط والحساب المعلق وفروق المطابقة. إغلاق الفترة يمنع تعديل أو عكس قيودها؛ أي تصحيح لاحق يجب أن يكون بقيد في فترة مفتوحة.

## التراجع

قبل تطبيق الأرصدة الافتتاحية يمكن التراجع بالكود و`migrate:rollback` ضمن نسخة احتياطية مجرّبة. بعد بدء تسجيل حركات فعلية لا تحذف جداول المحاسبة ولا تعمل rollback مباشرًا؛ أوقف التطبيق، خذ نسخة جديدة، وراجع القيود المسجلة وخطة الترحيل مع المحاسب.
